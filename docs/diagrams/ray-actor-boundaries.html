Why the LLM has to be built inside the actorLLM은 왜 액터 안에서 만들어야 하는가

supervisor_invoke() crosses two OS process boundaries to answer one supply-chain request. Ray can only carry plain, picklable data across those boundaries — so the bound, tool-calling LLM client is never passed in; each SpecialistActor builds its own the moment it starts. supervisor_invoke()는 공급망 요청 하나에 답하기 위해 OS 프로세스 경계를 두 번 넘습니다. Ray는 그 경계를 넘길 때 평범하고 pickle 가능한 데이터만 실을 수 있어서, 도구가 바인딩된 LLM 클라이언트는 넘기지 않습니다. 각 SpecialistActor가 시작하는 순간 자기 것을 직접 만듭니다.
